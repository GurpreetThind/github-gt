git switch is a relatively new command (introduced in Git 2.23) designed to do one thing and do it well: change branches.

Before this, we used git checkout for everything—switching branches, restoring files, and jumping to specific commits. git switch was created to make the process more intuitive and less error-prone.
-----------------------


Action,Command
Switch to an existing branch  ------> git switch <branch-name>
Create a new branch and switch to it ----->  git switch -c <new-branch-name>
Switch back to the previous branch ------> git switch -
Switch to a remote branch ------> git switch <remote-branch-name>

The -c stands for create. It is the modern equivalent of git checkout -b


If you try to switch to a branch that doesn't exist locally but does exist on your remote (like origin), Git will "guess" that you want to create a local tracking branch for it.

git switch develop
# If 'develop' only exists on GitHub, Git creates it locally for you.


Just like cd - takes you to your previous directory in the Mac terminal, git switch - takes you back to the last branch you were on. This is incredibly useful for quick toggles between a feature branch and main.


git switch vs. git checkout
While git checkout still works, here is why you should prefer switch:

Clarity: switch only moves you between branches. It won't accidentally overwrite a file in your working directory (which checkout can do if you type a filename instead of a branch name).

Safety: It has better built-in checks to ensure you don't lose uncommitted changes when moving between branches.

Complementary Tool: Its "partner" command is git restore, which is now used specifically for undoing changes to files.
